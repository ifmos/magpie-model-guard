# Magpie Model Guard

Magpie 插件：**模型级别**的降智检测与禁用。定时用可自动判分的探针题检测指定模型，检测未通过即拦截该模型的后续请求；支持自定义题目，适用于任意 `provider/model`。

- 探针经 Magpie 网关的 Chat Completions 接口发出，不绑定任何供应商或账号体系，**任意模型可用**。
- 检测题内置「糖果推理」；内置和自定义题均可编辑题目、预期答案与判分规则（数字 / 包含 / 精确 / 正则）。
- 支持原有固定间隔与 codex-guard 风格的分阶段检测；全局默认、单模型覆盖和每日探针预算。
- Go 后台（单二进制，内嵌 Web 控制台）+ Magpie JS 插件宿主 + 网关门禁中间件。

## 工作流程

```text
客户端 -> Magpie 网关 -> model-guard 门禁中间件 -> 上游模型
                         |
                         +-- 无禁用状态 ----------------> 直接放行
                         +-- 探针别名请求 ------------> 剥掉前缀后放行（防自拦截）
                         +-- 人工禁用 / failed / unavailable -> 403 拦截，不发往上游

定时调度器 --到达检测时间--> 用选中题目探针 --> 判分
    pass  -> state=passed，按 interval 排下一轮
    fail  -> 同题独立复测一次，两次皆错 -> state=failed（禁用），按失败复检间隔复测
    error -> state=unavailable（保守禁用），冷却后重试；不计为答错
```

门禁文件由 Go 后台在每次状态变化时原子重写，Magpie 在一秒内热加载。探针请求使用
内部别名 `model-guard-probe/<alias>/<model>`，门禁剥掉前缀后放行，避免探针被自己拦截。

**路由组隔离：** 插件启动的 Go 后台会同步本机 Magpie 的路由组配置。禁用具体模型后，显式组通过原生 `off` 排除该成员；自动组临时保存为同 ID 的受管组，健康成员继续处理业务请求。Manual 组会选择可用成员，全部禁用时停止转发。直接请求仍由中间件返回 403，探针继续按原始模型 ID 复测。

恢复时只撤销插件添加的停用项，保留用户原有停用、规则、权重等配置；未被用户修改的临时自动组恢复为原生派生组。状态变化立即触发同步，后台约每 10 秒检查配置变化和临时放行到期。同步异常在控制台明确显示，此时不能将直接请求门禁视为路由组隔离已成功。

路由组同步需要本机可执行的 `magpie`，默认读取 `$XDG_CONFIG_HOME/magpie` 或 `~/.config/magpie`；可通过插件选项 `magpieConfigDir`、`magpiePath` 指定配置与可执行文件，或直接启动后台时传 `-magpie-config <dir> -magpie <binary>`。配置目录须对应 Magpie 的 XDG 实例。独立启动未传 `-magpie-config` 时仅启用直接请求门禁。

Magpie 自身绕过中间件的内部请求不在直接请求门禁范围；中间件被关闭或加载失败时也无法提供该门禁。
此插件的判分只反映题目表现，不是模型身份认证。

## 安装

### 从 GitHub 安装（无需 Go）

在 Magpie 的 GitHub 插件安装入口填写：

```text
github:ifmos/magpie-model-guard
```

也可通过 CLI 安装：

```sh
magpie plugin add github:ifmos/magpie-model-guard
```

从 `0.1.1` 起，仓库随附 macOS Intel / Apple Silicon、Linux AMD64 / ARM64、
Windows AMD64 五个平台的预编译后台，运行机器不需要安装 Go 或自行构建。
若旧版本提示“找不到 Go 后台二进制”，请更新插件；若安装缓存未刷新，移除后重新添加，
再重启 Magpie 或关闭后重新启用插件。此修复不修改用户的数据目录。

`0.3.1` 修复了 `0.3.0` 路由组发现过程中递归加载插件、产生多个后台并争用侧车锁的问题。若看到「获取路由侧车锁失败 / context deadline exceeded」，请更新插件后重新启动 Magpie，使旧后台与宿主连接结束；不需要删除锁文件或清空检测数据库。

路由发现子进程现在只跳过 Model Guard 自身的后台启动，保留其它供应商和账号插件；CLI 查询在文件锁外执行。插件后台随宿主管道关闭而退出，避免插件宿主异常结束后留下调度进程。


### 从源码构建

需要 Go 1.26+：

```sh
go build -o bin/model-guard ./cmd/model-guard
magpie plugin add /absolute/path/to/magpie-model-guard
```

开发目录需包含 `plugin/`、`bin/model-guard`、`package.json`。跨平台构建：

```sh
sh scripts/build.sh
```

（产物：`bin/model-guard-<platform>-<arch>`，插件会按当前系统自动选择。）

### 首次配置

1. Magpie 插件入口 →「打开 Model Guard 控制台」。
2. 「连接设置」确认网关 URL 与 Key（本机默认 `http://127.0.0.1:3425` / `magpie`；插件会自动发现）。
3. 「监测目标」→ 刷新模型 → 下拉搜索模型 ID / 供应商，勾选一个或多个目标 → 添加监测。
4. 点「重测」立即跑一轮，确认链路正常。

## 检测规则

内置题库：

| ID | 题目 | 自动判分 | 规则 |
| --- | --- | --- | --- |
| `candy` | 糖果推理 | 是 | 默认期望数字 `21`；`121`、`21.5` 不匹配，可在编辑弹窗修改期望 |
| `repeat` | 逐字复述 | 否 | 人工评价 |
| `japan` | 知识覆盖 / 日本首相 | 否 | 人工评价 |
| `person` | 知识覆盖 / 人物 | 否 | 人工评价 |
| `svg` | SVG 创作 | 否 | 人工评价 |

「检测题库 → 编辑」可修改内置和自定义题目的名称、正文、预期答案、判分类型及是否参与自动检测。
保存后新探针使用新规则，重启不会覆盖编辑结果；内置题不可删除。新增题目使用「新建题目」。判分类型：

- `number`：匹配完整数字文本，拒绝将期望数字作为更长整数或小数的一部分；
- `contains`：回答包含期望关键字；
- `exact`：去除首尾空白后完全相等；
- `regex`：正则匹配（保存时校验）；
- 勾选「参与自动门禁」的题目才会影响模型状态。

一轮检测对目标的每道自动题各发一次请求；任一题失败会**独立复测一次**，两次皆错才判定
降智（`failed`，禁用）。网络错误、超时、HTTP 非 200、空回答、截断、预算耗尽均记为
`unavailable`：保守禁用但不计为答错，冷却（默认 15 分钟）后自动重试。

### 状态与操作

| 状态 | 含义 | 门禁 |
| --- | --- | --- |
| `unknown` | 从未检测 | 放行 |
| `checking` | 检测中 | 保留已有禁用状态 |
| `passed` | 上轮通过 | 放行 |
| `failed` | 降智（连续两次答错） | **403 拦截** |
| `unavailable` | 检测不可用 | **403 拦截**（保守） |
| `review` | 人工暂停 | **403 拦截** |

操作明确分离：

- **禁用模型**：设置持久化的人工禁用标记，业务请求返回 403，检测探针仍可访问。即使复测通过也不会自动解除人工禁用。
- **解除禁用**：清除禁用状态，不改变自动检测开关；下一轮检测失败仍会重新禁用。
- **暂停 / 恢复检测**：只改变定时调度，暂停检测不会解除已存在的禁用。
- **重测**：立即执行一轮检测，暂停自动检测时也可使用。
- **临时放行 15 分钟**：到期后继续执行原禁用策略。
- **删除目标**：移除监测和该目标的门禁。

自动检测造成的禁用在复检通过后恢复；人工禁用优先于检测结果。
旧版“停用”仅表示暂停检测，升级后保留这一状态；若要阻止业务请求，请点击新版“禁用模型”。

### 分阶段自动检测

从 `0.3.0` 起，可在「连接设置 → 全局分阶段调度策略」选择分阶段模式，点击「codex-guard 预设」填入下列间隔。已有配置升级后默认保持固定模式；也可在目标行的「策略」弹窗选择继承全局、固定模式或分阶段模式，并为该模型单独覆盖间隔。

| 阶段 | 默认等待时间 | 行为 |
| --- | ---: | --- |
| 正常检测 | 30 分钟 | 检测所选自动题 |
| 答错复测 | 2 分钟 | 复测原题，连续 3 轮答错才禁用 |
| 首次隔离复测 | 6 小时 | 保持禁用，复测导致隔离的原题 |
| 后续隔离复测 | 24 小时 | 隔离后再次答错，继续禁用 |
| 恢复确认 | 2 分钟 | 第一次通过保持禁用，第二次连续通过才恢复 |
| 检测不可用 | 30 分钟 | 立即保守禁用，中断恢复连续通过计数 |

六项间隔均可设置为 1–43200 分钟。单次超时和每日预算仍然生效。人工禁用不会被检测结果解除；原复测题被删除或取消自动判分时记为不可用，避免通过其它题目误恢复。

保存策略默认保留已经排好的 `next_check_at`；勾选「重新计算下次检测时间」才按当前阶段重新安排，正在运行的检测不重排。重启保留阶段、复测题和检测期限。固定模式仍使用单轮内立即独立复测一次、两次答错禁用、一次通过恢复的原有规则。


### 预算与超时

- 每模型每日探针请求上限（默认 120，可设 1–10000）；
- 单次请求超时默认 180s，`max_tokens` 8192；
- 固定模式默认检测间隔 30 分钟，可按目标设置 1–43200 分钟；
- 固定模式失败复检默认 60 分钟；分阶段模式按上表分别设置。

## 数据与安全

- 状态存于 `~/.config/magpie-model-guard/model-guard.db`（SQLite）；
- 管理 API 仅监听回环地址，Bearer token 鉴权，token 由插件入口注入控制台 URL；
- 探针只经过 Magpie 网关，不持有上游供应商凭据；路由同步只管理 `providers.json` 中受影响组的字段，保留供应商与未知配置数据。
- 路由恢复账本和待提交事务存于插件 SQLite，重启继续处理隔离与恢复。用户修改受管字段时停止覆盖冲突组，并显示组 ID 与冲突字段；请先在 Magpie 中处理冲突。
- 同步使用插件侧文件锁、写前字节检查和原子替换；Magpie 原生配置写入不共享此锁，因此应避免同时编辑正在同步的组。原生程序在最后检查与替换之间的并发写入仍存在竞争窗口。
- 临时保存的自动组在隔离期间使用保存的成员列表；完全恢复后返回 Magpie 动态发现。禁用或卸载插件前，先解除禁用或删除相关监测目标，等待路由同步恢复；直接退出后台会保留隔离配置。

## 验证

`go test ./...` 覆盖状态转换、配置迁移、恢复账本、锁竞争恢复与并发提交；`node --test tests/*.test.mjs` 检查门禁、无需 Go 的安装启动及宿主管道断开后的退出。
构建后运行 `node scripts/verify-auto-routing.mjs`，可使用真实 Magpie、完整插件包和两个本地测试上游验证显式组、自动组、直接请求门禁、探针、全组禁用与重启恢复。脚本使用独立临时 XDG 目录，完成后清理进程和数据；可用 `MAGPIE_TEST_BINARY` 指定 Magpie 可执行文件。
